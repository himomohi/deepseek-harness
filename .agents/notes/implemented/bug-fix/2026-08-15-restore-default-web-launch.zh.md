# Agent Note: 恢复默认 Web 启动

Status: implemented

[English](2026-08-15-restore-default-web-launch.md) | 中文

## Problem

修复无关的提供方和安全缺陷时，分叉的一键 Web 入口也被移除。此后，直接运行 `dsh` 会在 Web profile 暴露韩语 UI、OpenCodex、窄屏布局、更新、停止和流式改进之前失败。停止命令也无法识别进程命令停在裸源码或构建后 CLI 入口的 Web 服务器。

无条件启动浏览器对管道和无界面自动化同样不安全。缺少桌面命令时可能触发未处理的子进程错误，而独立进程组也无法为 Harness 提供有用的所有权。

## Decision

没有 `--profile` 时，根启动器选择 `web` profile。启动器 flag 和位于开头的应用 flag 继续交给 Web 提供方；未知的第一个位置 token 会按未知命令失败，空 `--profile` 仍然无效。

只有 stdout 属于交互式终端且没有 `--no-open` 时，Web 启动提供方才启用浏览器打开。Loader 树结算且规范 URL 就绪后，Web 运行时打印该 URL、输出本地化进度行，并将 URL 交给操作系统的默认浏览器命令。短期交接进程不会进入独立进程组；同步和异步启动错误都会打印手工打开 URL，而不会停止服务器。

除显式 `web` 与 `--profile web` 形式外，`dsh stop` 还会识别裸源码、构建后和已安装 CLI 入口。`dsh update` 会检查所有仍在维护的分叉功能标记，而不再只检查韩语与 OpenCodex 包。

## Alternatives considered

**永久要求 `dsh web`。** 拒绝，因为一键启动是该分叉的有意功能。单独拒绝未知的开头位置参数，可以在不移除默认值的情况下阻止命令拼写错误。

**为每个 Web 进程打开浏览器。** 拒绝，因为管道和自动化运行不拥有桌面交互。交互式 stdout 加上 `--no-open` 使默认行为可观察且可控制。

**回退完整的修复提交。** 拒绝，因为其中仅限回环地址的管理操作、有界的提供方行为、共享流式运行时、浅层历史修复和仓库质量修复仍然必需。

## Consequences

交互式 `dsh` 默认会进入 Web UI 并打开其 URL。管道运行会启动同一个服务器但不打开浏览器，`--no-open` 则为终端提供显式退出选项。拼错的位置命令仍会在启动前失败。

本决策不会恢复已移除的无界 `max-tokens` 自动续写和未接线的 Vision Fallback。重新引入这些功能仍需要显式预算、持久化的模型可见状态、真实提供方传输和可运行证据。
