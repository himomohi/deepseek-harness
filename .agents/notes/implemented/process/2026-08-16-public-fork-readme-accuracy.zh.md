# Agent Note: 保持公开分支 README 为当前且可验证的说明

Status: implemented

[English](2026-08-16-public-fork-readme-accuracy.md) | 中文

## Problem

后续功能提交持续替换或扩展 README 内容时，公开 README 丢失了早期文档更新引入的视觉层次。直接完整恢复该旧版本也会恢复仓库无法验证的声明，包括固定的模型目录数量和提供方性能改进。现有安装章节也没有为新用户足够醒目地区分官方 npm 软件包与此源代码分支的实际差异。

## Decision

根 README 将此仓库表述为受维护的 `himomohi/deepseek-harness` 分支，同时保留 DeepSeek AI 作为上游项目所有者。首个安装表格在介绍分支独有功能前，明确区分官方 `npx @deepseek-ai/dsh web` 软件包和克隆的分支工作区。

功能概览只列出当前源代码和维护变更日志中存在的行为：韩语区域设置插件、实时 OpenCodex 模型发现、默认 Web 启动和浏览器交接、受维护的停止路径、手机宽度布局、基于游标的串流队列、交互式上游更新、仅环回的敏感 RPC 表面、提供方感知的输出限制、标题栏任务取消，以及可选的浏览器通知。徽章可以显示稳定的项目事实，但不显示模型数量、版本号、性能百分比或其他容易过期的值。

变更日志负责版本时间线。README 负责当前能力概览、启动路径、常用命令、安全限制和详细文档链接。英文、中文和韩语页面采用相同的章节结构和声明。

公开树保留产品源代码、测试、变更日志条目和必需的 Agent Note，因为它们说明或验证受维护的行为。`WORK_RESUME.md` 等本地会话延续文件不属于项目文档并保持忽略状态，测试夹具则使用中性的工作区路径，而不是维护者的主目录。

## Alternatives considered

**不加修改地恢复早期视觉 README。** 这种方法可以快速恢复展示效果，但也会重新发布未经验证的缓存命中率、首令牌时间、成本和目录数量声明。

**保留最简的上游风格 README。** 这种方法减少展示维护，但隐藏了分支入口，并使当前分支能力难以发现。

**在徽章中显示实时版本和模型数量。** 这些值会在软件包清单、变更日志和发现的提供方目录之间独立变化，因此静态徽章会再次形成过期的公开声明。

## Consequences

新用户可以在安装前判断需要官方软件包还是维护分支。公开功能声明可以追溯到当前仓库行为，而不是历史营销文本。当前树不再公开本地会话交接文档或维护者专用的绝对路径。列出的能力发生变化时，未来维护者必须更新三种语言的 README，而逐版本细节继续保留在变更日志中。
