# Agent Note: 移除缺乏证据的模型自动化

Status: implemented

[English](2026-08-15-remove-unevidenced-model-automation.md) | 中文

## Problem

该分叉加入了三项模型路径变更，却没有它们所需的证据或生命周期约定。Agent loop 会把每个纯文本 `max-tokens` 结束转换为另一次付费请求，且没有次数上限。DeepSeek 序列化会在普通 assistant 轮次回传 `reasoning_content`，但提供方只要求工具调用轮次回传，并会忽略其他轮次的该字段。Vision Fallback 包宣称自动图片理解，但没有任何请求路径调用其消息转换器：仅仅存在该服务就会绕过图片准入，而文本适配器随后仍拒绝图片；其进程级描述缓存也没有上限。

这些变更使 UI 宣称连续输出、缓存改善和视觉支持，而组装后的应用无法证明它们。视觉路径还违反模型可见内容日志规则：生成的描述在替换图片内容前，必须拥有持久事件和确定性的请求重建。

## Decision

`max-tokens` 再次成为终止状态。Loop 记录并返回该原因，不注入用户消息，也不启动另一请求。调用方可以通过显式用户动作或另行设计的有界策略决定是否继续。

DeepSeek 与 OpenCodex 只在同一个 assistant 轮次携带工具调用时序列化 `reasoning_content`。普通轮次和纯推理轮次保留可见文本，但不会再次发送被忽略的推理。

Vision Fallback 包、bundle 行、Models 卡片、语言文案、缓存和图片准入绕过全部删除。纯文本模型会在提供方 I/O 前拒绝图片提示和 `read_image` 调用。即使模型 id 通常与视觉能力相关，OpenCodex 也声明为仅文本，因为该适配器没有附件字节的 wire 实现。

## Alternatives considered

**限制缓存大小并继续挂载 Vision Fallback。** 拒绝，因为内存并非主要正确性缺陷。组装请求没有消费生成的描述，仅凭服务存在允许图片只会产生稍后的适配器失败，而不是视觉输出。

**在 `llm/stream` waterfall 中转换消息。** 拒绝，因为 loop 构建的请求是 Session 日志的冻结函数。模型可见描述需要新的持久事件、回放规则、失败语义和 snapshot 覆盖；在中间件中修改请求会破坏重建。

**把自动续写限制为固定重试次数。** 本次变更拒绝，因为续写文本、预算、计费同意、截断工具调用语义和用户可见 transcript 仍需要产品约定。返回 `max-tokens` 可以保留提供方事实，而不虚构策略。

**为假定缓存命中重发普通轮次推理。** 拒绝，因为提供方文档说明该字段会被忽略，缓存复用是尽力而为，而且没有提供方侧 A/B 测量证明收益足以抵消额外输入 Token 或兼容性风险。

## Consequences

在这些能力具备显式预算、持久事件、提供方 wire 支持、可运行 snapshot 与真实提供方证据前，该分叉放弃自动长输出续写和自动图片描述。用户会看到真实的终止或模态错误，而不是静默额外请求或虚假接受。

模型路径现在符合官方回传指南，不再拥有进程级视觉缓存。既有游标流式队列保持不变；其实测本地积压收益不依赖任何已删除自动化。
